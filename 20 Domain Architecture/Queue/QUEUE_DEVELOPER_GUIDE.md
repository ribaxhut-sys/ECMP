## Hard rules

- Immutable `QueueTicket` — never mutate fields in place
- Ticket lifecycle uses `QueueTicketStatus` (not `QueueStatus`)
- **All** status transitions validated by Domain — never from controllers
- Ticket numbers generated by Domain (`TicketNumberGenerator`) — never hardcoded in API
- Domain / application packages: no SQLAlchemy / ORM imports
- Repository interfaces: persistence only — no business rules
- Application orchestrates only — no business logic
- Persistence (TASK-063): `interfaces/` · `orm/` · `mappers/` · `repositories/` ·
  `infrastructure/` — see `QUEUE_PERSISTENCE_DEVELOPER_GUIDE.md`
- REST: `api/` — see `QUEUE_REST_API.md`
- Policy is enum-only (FIFO / PRIORITY_QUEUE) — no scheduling engine

## Operations (CAPABILITY-003)

| Domain / Application | REST |
|---|---|
| `open_queue` | `POST /api/v1/queues/{id}/open` |
| `close_queue` | `POST /api/v1/queues/{id}/close` |
| `issue_ticket` | `POST /api/v1/queues/{id}/issue-ticket` |
| `call_next` | `POST /api/v1/queues/{id}/call-next` |
| `recall_ticket` | `POST /api/v1/tickets/{id}/recall` |
| `complete_ticket` | `POST /api/v1/tickets/{id}/complete` |
| `skip_ticket` | `POST /api/v1/tickets/{id}/skip` |
| `cancel_ticket` | `POST /api/v1/tickets/{id}/cancel` |

Happy path: `WAITING → CALLED → (SERVING) → COMPLETED`.
Forbidden: `WAITING → COMPLETED` directly.
