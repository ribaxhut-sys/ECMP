## Objective

Expose Queue bounded-context capabilities through REST using Clean
Architecture, DDD, SOLID, and API-First principles.

Queue is **visit context only**. Queue and Complaint lifecycles stay separate.

Queue is an **operational queue** (CAPABILITY-003): open/close, issue,
call-next, recall, complete, skip, cancel — not CRUD alone.

## Architecture

```text
HTTP Request
    ↓
Router (FastAPI)
    ↓
Controller (HTTP ↔ Application translation only)
    ↓
QueueCrudApplicationService | QueueOperationsApplicationService
    ↓
Repository Interface (ABC)
    ↓
SqlAlchemy*Repository + Mapper
    ↓
PostgreSQL
```

### Layers

| Layer | Package | Responsibility |
|---|---|---|
| API | `queue/api/` | Controllers, routers, request/response DTOs, validators, DI |
| Application | `queue/application/` | CRUD + Operations orchestration (no business rules) |
| Domain | `queue/models.py` + `queue/domain/` + `QueueDomainService` | Lifecycle, ticket numbers, selection |
| Persistence | `queue/interfaces` + `repositories` + `orm` + `mappers` | Ports & adapters only |

### Non-goals (STOP)

- Display / Kiosk / Voice
- Complaint / Workflow / Notification APIs
- Redis / WebSocket / Background Worker / Dashboard
- Authentication / Authorization / Audit enforcement

## Lifecycle

### Queue status

`OPEN` · `CLOSED` · `PAUSED`

- Issue ticket requires **OPEN**
- **CLOSED** rejects new tickets

### Ticket status (domain-validated only)

```text
WAITING → CALLED → SERVING → COMPLETED
WAITING / CALLED → SKIPPED
WAITING / CALLED / SERVING → CANCELLED
CALLED / SERVING → recall (status unchanged)
```

Forbidden example: `WAITING → COMPLETED` directly.

Ticket numbers are generated by Domain (`TicketNumberGenerator`, default
`A001`, `A002`, …) — never hardcoded in controllers.

## DTO

### Request models

- `CreateQueueRequest` / `UpdateQueueRequest`
- `CreateTicketRequest` / `UpdateTicketRequest`
- `CreateCounterRequest` / `UpdateCounterRequest`

### Response models

- `QueueResponse`
- `QueueTicketResponse`
- `QueueCounterResponse` (includes `queueId` association)

Never return Domain Entity. Never return ORM. Envelope: `{ "data": ... }`.
`call-next` returns **204** when the waiting list is empty.

## Validation

- UUID path / query / body fields
- Enums: `QueueStatus`, `QueuePolicy`, `QueuePriority`, `QueueTicketStatus`
- String length / required / blank strip
- Issue ticket requires queue **OPEN** (else 409 `INVALID_STATE`)
- Ticket lifecycle transitions use Domain only

Platform maps FastAPI `RequestValidationError` → **400** `VALIDATION_ERROR`
(consistent with ECMP). OpenAPI also documents **422** for contract clarity.

## Error envelope

```json
{
  "code": "NOT_FOUND",
  "message": "queue not found: ...",
  "details": {}
}
```

| HTTP | When |
|---|---|
| 201 | Created |
| 200 | OK |
| 204 | Deleted / call-next empty |
| 400 | Validation / bad request |
| 404 | Missing resource |
| 409 | Conflict / invalid state |
| 422 | Documented validation (OpenAPI) |
| 500 | Unhandled |

## Dependency Graph

```text
QueueController / TicketController / CounterController
        ↓ Depends
QueueCrudApplicationService | QueueOperationsApplicationService
        ↓
QueueDomainService (rules + ticket number generator)
        ↓
QueueRepository | QueueTicketRepository | QueueCounterRepository
        ↓
SqlAlchemy*Repository (AsyncSession)
```

`RequestContext` (CAPABILITY-002 / `app.core.request_context`) is injected
into every controller method via `Depends(get_request_context)`. Stub headers:
`X-Request-Id`, `X-Correlation-Id`, `X-Organization-Id`, `X-Branch-Id`,
`X-User-Id` — no auth enforcement; ready for Authentication upgrade.
