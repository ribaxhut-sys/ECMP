- **Dashboard UI** — login/logout, complaints, queue, resolutions, attachments, settings, RBAC-gated actions

## Security

- JWT access token TTL **15 minutes**
- Refresh token **7 days**, hashed at rest, **rotated** on refresh, revoked on logout
- Refresh cookie: **HttpOnly**, **Secure** (non-dev), **SameSite=Lax**
- Secret guard blocks default/weak `JWT_SECRET_KEY` in staging/production
- Trusted Host enforcement outside development
- Security response headers (CSP, nosniff, frame deny, referrer, permissions-policy)
- Hardened CORS (explicit methods/headers; no `*` origins outside development)
- Interactive API docs disabled outside development
- Audit events: `auth.login`, `auth.refresh`, `auth.logout` (no token payloads)
- Access logs never include Authorization headers or token values

## Breaking Changes (vs pre-RC1)

Inherited from RC1; unchanged for Production:

- Dashboard requires login + refresh cookie (no static `NEXT_PUBLIC_ACCESS_TOKEN`)
- Access token TTL **15m**
- `/docs`, `/redoc`, `/openapi.json` unavailable when `ENVIRONMENT` ≠ `development`

## Known Limitations

- No MFA / SSO / OAuth / OIDC / LDAP
- No password reset / social login
- No email / WebSocket / push notification delivery channels beyond in-app queue
- No mobile client
- No Customer Master write-back (ECMP is not Customer Master SoR)
- Role→permission mapping remains code-seeded until Core Platform API-062 SoT promotion
- Broker-backed enterprise event bus out of scope for this Compose stack
- Combined health probe: `GET /health` (liveness + DB readiness)

## Deployment Notes

1. Copy `.env.example` → `.env`; set strong rotated `JWT_SECRET_KEY` (≥32 chars).
2. Set `ENVIRONMENT=production`, `APP_VERSION=1.0.0`, `ALLOWED_ORIGINS`, `ALLOWED_HOSTS`.
3. Take Postgres backup before upgrade.
4. `docker compose build && docker compose up -d`
5. Backend entrypoint runs `alembic upgrade head` then Uvicorn.
6. Verify `GET /health` → `status=ok`, `database=up`, `version=1.0.0`.
7. Run smoke test: login → complaint lifecycle → reports → logout.
8. Full checklist: [`docs/deployment-checklist.md`](../deployment-checklist.md)
9. Rollback: [`docs/releases/ROLLBACK_v1.0.0.md`](./ROLLBACK_v1.0.0.md)
