## Executive summary

**v1.0.0** is the Production release of the ECMP foundation stack. It promotes the
`release/v1.0.0` line after Release Candidates **rc2** (hardening), **rc3** (Identity &
RBAC), and **rc4** (password management UI / admin reset), plus post-rc4 readiness work:
production configuration hardening (R6-03), split health probes (B2), and TLS / reverse
proxy reference stacks (B3).

This document matches the approved release content at `release/v1.0.0` HEAD (`6cb12fe`)
and the B4 metadata sync in `CHANGELOG.md` / rollback runbook.

## Security

- JWT access TTL **15 minutes**; refresh **7 days**, hashed at rest, **rotated** on refresh, revoked on logout
- Refresh cookie: **HttpOnly**, **Secure** (non-dev), **SameSite=Lax**
- Secret / credential fail-fast: `JWT_SECRET_KEY`, `POSTGRES_PASSWORD`, optional `PGADMIN_DEFAULT_PASSWORD`
- Login brute-force lockout (in-memory; configurable; HTTP `429 RATE_LIMITED`)
- Production config guards (R6-03): CORS origins, password-reset base URL vs `ALLOWED_ORIGINS`, `EMAIL_PROVIDER`, `JWT_ALGORITHM`, `DEBUG`
- Password-reset production guards: no localhost reset URL; no `EMAIL_PROVIDER=logging` outside development
- Trusted Host + security headers (CSP, nosniff, frame deny, referrer, permissions-policy)
- Interactive API docs disabled outside development
- Edge TLS: HSTS; only ports **80/443** published on production compose; trusted `X-Forwarded-*` via `FORWARDED_ALLOW_IPS` + uvicorn proxy headers
- Audit / access logs omit token payloads and Authorization headers

## Breaking changes (operational)

- Staging/production **must** set strong secrets and production-valid CORS / reset URL / email provider before start
- Frontend production builds **must** set `NEXT_PUBLIC_API_BASE_URL`
- Prefer `GET /live` and `GET /ready` over a single combined probe for orchestration
- Production edge expected via Caddy or Nginx profiles (TLS termination for Secure cookies)

## Known limitations

- No MFA / SSO / OAuth / OIDC / LDAP / social login
- Production email delivery depends on configured `EMAIL_PROVIDER` (dev may use `logging`)
- Admin temporary password is shown once and cannot be re-fetched
- In-memory login lockout is per-process (not shared across replicas)
- No mobile client
- No Customer Master write-back (ECMP is not Customer Master SoR)
- Role→permission mapping remains code-seeded until Core Platform API-062 SoT promotion
- Broker-backed enterprise event bus out of scope for this Compose stack

## Deployment notes

1. Prefer production compose profiles (`docker-compose.prod.yml` or Nginx variant) with `.env.production` derived from `.env.production.example`.
2. Set `ENVIRONMENT=production`, `APP_VERSION=1.0.0`, strong `JWT_SECRET_KEY`, `ALLOWED_ORIGINS`, `ALLOWED_HOSTS`, production-valid password-reset URL and email provider.
3. Run `scripts/validate-production-config.py` before go-live.
4. Take Postgres backup before upgrade.
5. Backend entrypoint runs `alembic upgrade head` then Uvicorn.
6. Verify `GET /live` (liveness) and `GET /ready` (readiness, version `1.0.0`).
7. Smoke: login → password flows (as applicable) → complaint lifecycle → reports → logout.
8. Full checklist: [`docs/deployment-checklist.md`](../deployment-checklist.md)
9. Rollback: [`docs/releases/ROLLBACK_v1.0.0.md`](./ROLLBACK_v1.0.0.md) → tag **`v1.0.0-rc4`**
