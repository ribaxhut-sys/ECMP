## Release Candidate Summary

**v1.0.0-rc2** freezes the foundation stack after Sprint R1 re-validation and Sprint R2
production hardening. **No business features were added.** Changes are limited to:

- Windows/CI test reliability (R1)
- Runtime and Compose credential fail-fast (R2)
- Login brute-force protection (R2)
- Frontend production API URL build guard (R2)
- RC packaging docs: changelog, notes, smoke, UAT accounts (R3)

Promote to final Production only after UAT sign-off against this tag and a rebuild of
Compose images from `release/v1.0.0`.

## Security Improvements

- JWT secret guard (existing) retained; docs/API docs remain disabled outside development.
- **R2-01:** Outside `ENVIRONMENT=development`, weak/default `POSTGRES_PASSWORD` and
  (when set) `PGADMIN_DEFAULT_PASSWORD` cause startup failure.
- **R2-03:** In-memory login lockout (default 5 failures / 300s) returns `429 RATE_LIMITED`
  keyed by client IP + username. Configurable; no Redis dependency; login API contract unchanged.
- Refresh cookie **HttpOnly** / **Secure** (non-dev) / **SameSite=Lax** unchanged.
- Trusted Host + security headers + hardened CORS unchanged.

## Configuration Hardening

- **R2-02:** `docker-compose.yml` requires `POSTGRES_PASSWORD`, `JWT_SECRET_KEY`,
  `PGADMIN_DEFAULT_PASSWORD` (tools profile), and `NEXT_PUBLIC_API_BASE_URL` via `.env`
  (`${VAR:?…}`). Weak `:-ecmp` / `:-admin` / `:-change-me-in-production` fallbacks removed.
- Local developer convenience preserved only through `.env.example` → `.env` while
  `ENVIRONMENT=development`.
- **R2-04:** `frontend/next.config.ts` and `frontend/Dockerfile` fail production builds if
  `NEXT_PUBLIC_API_BASE_URL` is missing. `next dev` may still fall back to localhost.
- Root frontend CI sets the API URL explicitly for builds.

## Included Capabilities (unchanged surface)

Auth, Complaints, Assignment, Escalation, Resolutions, Appointments, Timeline, Queue, SLA,
Attachments, Notifications, Search, Reporting/KPI/Dashboard, Users/IAM, Branches/Customers,
Settings, Audit, Dashboard UI — as documented in `docs/releases/v1.0.0.md`.

## Breaking / Operational Notes

- Staging/production deployments **must** set strong `POSTGRES_PASSWORD` and `JWT_SECRET_KEY`
  before start (runtime + Compose fail-fast).
- Frontend image builds **must** pass `NEXT_PUBLIC_API_BASE_URL` (Compose build-arg / CI env).
- Login abuse now yields **429** after lockout threshold (clients should surface retry guidance).

## Known Limitations

- No MFA / SSO / OAuth / OIDC / LDAP / password reset.
- Login lockout is per-process (not shared across replicas).
- Combined health probe: `GET /health`.
- Role→permission map remains code-seeded until Core Platform API-062.
- See also known limitations in `docs/releases/v1.0.0.md`.

## Deployment Notes

1. Checkout `release/v1.0.0` @ tag `v1.0.0-rc2`.
2. Copy `.env.example` → `.env`; set strong secrets for non-dev targets.
3. Set `NEXT_PUBLIC_API_BASE_URL` to the browser-reachable API origin.
4. `docker compose build && docker compose up -d`
5. Verify `GET /health` → `status=ok`, `database=up`.
6. Execute smoke report + UAT accounts guide.
7. Checklist: `docs/deployment-checklist.md`
